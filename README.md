# Падающая звезда — сканер OKX с сообщениями в Telegram

Бот проверяет самые ликвидные USDT-перпетуалы OKX и присылает сообщение в Telegram, как только на 1ч или 4ч закрылась свеча «падающая звезда». Правила звезды перенесены из индикатора TradingView «Shooting Star Strategy Helper v3» (файл `tradingview/shooting_star_helper.pine`).

## Как это работает

Бот проверяет закрытую свечу на 1ч и 4ч. Сообщение приходит, только если выполнены все условия:

1. **Форма свечи.** Тело не больше 35% диапазона, верхняя тень не меньше 50%, нижняя не больше 15%, верхняя тень не меньше 2 тел.
2. **Размер.** Диапазон свечи не меньше 0.5 ATR(14): крошечные свечи на тихом рынке отсекаются.
3. **Тренд.** Закрытие выше SMA20, SMA растёт, три свечи подряд (считая звезду) закрылись выше SMA.
4. **Максимум.** Максимум звезды не ниже максимумов предыдущих 10 свечей.
5. **RSI(14) на звезде не ниже 70.** Звёзды с RSI ниже 70 бот не учитывает.

Сообщение приходит сразу после закрытия свечи-звезды. Подтверждения (закрытие ниже минимума звезды на 15м/30м) по умолчанию не отслеживаются и сообщений о них нет. Если они понадобятся, включите `CONFIRM_ALERTS = True` в `config.py`.

Бот запоминает, какие звёзды уже видел, поэтому одна и та же свеча не отправляется дважды. По умолчанию пауз между сообщениями по одной монете нет (`STAR_COOLDOWN_HOURS = 0`): вы увидите каждую подходящую свечу.

## Что в сообщении

```
🌠 Падающая звезда · SOL/USDT

Свеча-звезда 1ч сформировалась.

Цена сейчас: 105.85 (19:16, Ташкент)
Звезда: 1ч, закрылась 27.10 19:00
RSI(14) на звезде 1ч: 74 (перекупленность)
Тренд: 12 св. подряд выше SMA20, цена +3.2% от неё
Свеча: размер свечи ×1.8 от ATR, объём ×2.5 от среднего

Максимум звезды: 108.45 · минимум: 106.15

График TradingView
```

Цифры в примере условные. Все времена по Ташкенту. Уровней входа бот не предлагает: решение принимаете вы.

## Скорость работы

Между запросами к бирже бот делает паузу 8 секунд (`REQUEST_PAUSE`), чтобы биржа не блокировала адрес GitHub. Поэтому проход по 75 монетам на одном таймфрейме занимает около 10 минут, и сообщение может прийти через 10-15 минут после закрытия свечи (плюс задержка расписания GitHub). За один запуск звёзды ищутся только на одном таймфрейме. При совпадении закрытий сначала проверяется 4ч, затем 1ч — следующий запуск проходит примерно через 15 минут.

Чтобы сообщения приходили быстрее:
- уменьшите `TOP_COINS` (при 30 монетах проход занимает около 4 минут);
- осторожно уменьшайте `REQUEST_PAUSE`: если биржа начнёт отвечать ошибками, верните прежнее значение.

Если биржа недоступна, поиск прерывается после 5 ошибок подряд, а запуск в любом случае укладывается в 25 минут.

## Установка (один раз)

1. На GitHub создайте новый репозиторий. Лучше **Public**: в публичных репозиториях Actions бесплатны без ограничения по минутам, а в приватных 2000 бесплатных минут в месяц не хватит на запуск каждые 15 минут. В коде нет паролей, секреты хранятся отдельно.
2. Распакуйте архив и загрузите все файлы в репозиторий: Add file → Upload files. Папку `.github` тоже нужно перетащить.
3. Settings → Secrets and variables → Actions → New repository secret. Добавьте два секрета:
   - `TELEGRAM_BOT_TOKEN` — токен бота из @BotFather;
   - `TELEGRAM_CHAT_ID` — номер вашего чата.
4. Вкладка Actions → слева «Scan» → Run workflow → отметьте `test_telegram` → Run. В Telegram должно прийти тестовое сообщение.
5. Чтобы включить основную 15-минутную цепочку, запустите workflow ещё раз без `test_telegram` и `dry_run`. Проверочный запуск с тестом или dry run цепочку не запускает. Резервный cron запускает одиночную проверку каждые 15 минут.

Если в Actions кнопка Run workflow не появилась, нажмите на вкладке Actions «I understand my workflows, go ahead and enable them».

## Настройки

Все числа в файле `config.py`. Изменить файл можно прямо на GitHub (значок карандаша) и сохранить кнопкой Commit.

- **Слишком мало сообщений:** поставьте `RSI_LOOKBACK = 2` или `3` (достаточно, чтобы RSI был не ниже порога на звезде или на одной из предыдущих свечей), уменьшите `MIN_BARS_ABOVE_SMA` или выключите `REQUIRE_RISING_SMA`.
- **Слишком много сообщений:** поднимите `RSI_MIN` до 75, включите `REQUIRE_DIVERGENCE = True` (медвежья дивергенция) или `MIN_VOLUME_MULT = 1.5`.
- **Порог RSI:** `RSI_MIN = 70`. Всё, что ниже, бот не присылает. Чтобы вообще не проверять RSI, поставьте `RSI_FILTER = False`.
- **Вечерняя звезда:** в индикаторе её нет, поэтому она выключена. Включается через `EVENING_ENABLED = True`; фильтры тренда, RSI и размера применяются и к ней.
- **Сообщения о падении:** `CONFIRM_ALERTS = True` возвращает схему «звезда → закрытие свечи 15м/30м ниже минимума звезды».

## Как проверить, что бот работает

Actions → любой запуск → Scan → шаг «Запуск сканера». В конце лога строка «Итог»: сколько монет проверено, сколько ошибок запросов к бирже, сколько новых звёзд и сколько сообщений отправлено. Если ошибок много, увеличьте `REQUEST_PAUSE` в `config.py`.

Пробный запуск без отправки в Telegram: Run workflow → `dry_run`. Текст сообщений появится в логе. Такой запуск не продолжает рабочую цепочку.

## Важно

- GitHub запускает расписание с задержкой, иногда в несколько минут. Сообщение может прийти не точно в момент закрытия свечи.
- В публичном репозитории без изменений GitHub выключает расписание через 60 дней. Тогда на вкладке Actions нужно нажать Enable.
- Это инструмент поиска ситуаций, а не гарантия результата.
